Step 5 Preview 开放权重：从 API 到可自行部署，阶跃这次交付了什么？

狂人哥2026-10-17— 次阅读
SI&AI资讯

9 月听到 Step 5 Preview 发布的人，到了 10 月又看到一轮“开源”消息，很容易以为阶跃星辰发布了第二个新模型。两次消息对应的交付阶段其实不同：此前可以通过产品和 API 调用，10 月 15 日则把可下载权重交给了外部开发者。

本文在 10 月 17 日核对了 阶跃星辰官方 BF16 模型仓库、运行说明和许可证。对这次消息，更合适的关注点是：别人现在能独立做哪些事，还需要自己补上哪些部分。

从可调用，到能自己运行

把最近几个时间点放在一起，变化就清楚了：

  • **9 月 20 日：**Step 5 Preview 上线，面向软件工程、研究分析等需要多次执行工具的任务。原始发布页面 说明产品和 API 已开放，并预告 10 月 15 日释放权重；页面目前仍保留这段历史预告。
  • **10 月 12 日：**据 IT之家当天报道，模型进入腾讯 WorkBuddy，相关限免活动覆盖 10 月 12 日至 25 日。这属于应用入口扩展，与权重许可是两件事。
  • **10 月 15 日：**BF16、FP8 检查点和运行材料落地，官方同时发布架构与训练说明。Pandaily 当天的报道 也记录了这个交付节点。

使用 API 时，请求由服务提供方接收和运行。拿到权重后，团队可以在许可范围内研究模型、选择自己的基础设施，并考虑后续适配。新的自主空间来自能够获取和运行模型文件，不是模型在这一天突然获得了另一套已验证能力。

Step 5 Preview 采用稀疏混合专家架构，官方标注约 6000 亿总参数，每个 token 激活约 270 亿参数，支持最高 100 万 token 的上下文。稀疏激活减少的是每次计算所动用的部分，完整权重仍需要存储和加载。

交付物里，比“下载按钮”更重要的部分

官方部署说明 给出了 vLLM、SGLang 和独立 Transformers 实现等路径。前两者可以提供兼容 OpenAI 接口形式的服务；这是接口格式兼容，并不表示模型由 OpenAI 提供，也不保证所有客户端功能自动兼容。

运行环境的适配很关键。例如，模型输出中的推理内容、工具调用格式以及多 token 预测，需要框架相应支持。只把一个熟悉的模型名称替换进旧配置，未必就能得到完整能力。

SGLang 与 Miles 的支持说明 披露了具体运行结果：在四张 GB300、约 8K 输入、768 至 1,280 输出 token、指定 FP8 专家权重和推测解码配置下，单请求解码约为每秒 299 token。这是项目方给定环境下的测试，不能照搬成自己的服务器速度，更不能当成处理满百万上下文时的表现。

官方也保留了尚未完成验证的部分：Transformers 的完整 BF16 文件分片转换到生成流程，尚未完成端到端验证。因此，“权重已经开放”和“所有运行路径都已充分验证”，应当分别判断。

百万上下文背后，是怎样处理旧信息的？

长任务会不断累积代码、报错、工具返回和中间结论。如果每一步都反复读完所有历史，开销会迅速变大。阶跃 10 月 15 日的 技术文章 解释了它如何处理这个问题。

模型把主要关注近期内容的注意力层，与选择历史片段的稀疏注意力层交错安排。Sparse GQA 会先对历史内容按块建立索引，再选取相关部分参与计算。可以把它理解为：先查目录，找到需要的旧记录，再展开阅读，而不是每次从第一页翻到最后一页。

图源：阶跃星辰技术文章图 2，2026 年 10 月 17 日核查。该图展示历史块的选择与读取机制，不是业务任务成功率或速度对比图。

同一篇技术文章还介绍了上下文压缩训练：任务较长时，把进展整理成可继续执行的状态。这里的目标是让有限窗口支撑更长的工作过程，并不是证明模型能够无限记忆、永不遗漏。

这也与本站此前报道的 Anthropic 为巨型代码库开发 Scion 形成呼应：模型能力提升之后，任务记录、工具链和运行系统都在影响实际效率。

这份模型许可证，要看哪几处？

Step 5 的模型权重采用 StepFun Model License 1.0。许可证原文 允许在条件下使用、修改与分发，并设置了额外要求。它与标准 Apache 2.0 或 MIT 不能直接画等号。

其中有三处对商业使用尤其相关：

  1. 使用模型的商业产品或服务，如果某个自然月的活跃用户超过一亿，或月收入超过 2000 万美元，之后需要按条款显著展示指定署名。
  2. 面向终端用户销售硬件的制造商或品牌方，把模型能力作为设备或配套服务的商业功能提供时，需要另行商用许可；远程运行也在该条款覆盖范围内。
  3. 使用者或关联方经营对外提供模型推理或微调访问的 MaaS 业务，且合并各来源收入在任意连续十二个月超过 2000 万美元时，相关商业用途需要单独协议。原文还为不向第三方提供能力或输出的内部使用，以及认证渠道范围内的使用规定了例外。

这些门槛的统计周期与适用对象不同，不能合并成一个“收入超过某数就全部收费”的结论。计划实际部署时，应按自己的产品形态核对原文。

另外，Step Code 终端工具仓库 标注的 MIT 许可属于该工具，不能据此推断底层模型也采用 MIT。官方 API 文档同样说明：搜索、代码执行等能力由接入模型的应用提供，模型本身不会自动获得本机或外部服务的访问权。

对个人读者，这次最直接的变化，是后续有机会出现更多基于同一模型的服务和适配；对开发团队，则多了运行、评估和调整的选择。不过，自行部署仍意味着承担硬件、版本、服务维护与测试工作。是否划算，需要对实际任务算账，而不是只看榜单上的一次高分。

截至本文核查，权重开放已经落地；官方评测中的历史日期、特定运行配置和仍待验证的流程，也都应与这条新消息一起保留。补充能力边界可参阅 Step 5 Preview 官方 API 文档。

Kimi K3.1 Pro 发布，3D 创作与长任务成为升级重点

狂人哥2026-10-25— 次阅读
SI&AI资讯

Kimi K3.1 Pro 已进入月之暗面的产品线。这次升级把编程、3D 创作和金融研究放在一起，强调的是模型持续调用工具、修改作品并完成长任务的能力；同时推出的 Highspeed，则用更高的额度或费用换取更快输出。

Kimi Code 的更新记录将上线日期列为 10 月 23 日，技术博客索引则在 10 月 24 日收录了新模型。标准版和 Highspeed 已进入 Kimi 产品与 API；完整权重是另一项交付，官方计划在 11 月 4 日前发布。它尚不能被写成“权重已经可以下载”。

3D 创作的看点，是作品后面还有工作流

官方技术博客把 K3.1 Pro 定义为 K3 经更大规模后训练得到的新版本，提升集中在编程、3D 创作、金融研究等领域。这说明它延续了已有路线，重点是把长任务中的工具使用和多轮执行做得更好。

伴随发布，Kimi 网页版和应用提供了 3D Make：可以在线预览、编辑模型，下载适合后续 3D 打印的模型，或导出视频等内容。对普通用户而言，可编辑和可导出的交付物，比聊天窗口里一句“模型做好了”更容易检查。

来源：Moonshot 发布文原图，2026 年 10 月 25 日核查。图中模型栏保留 K3 High 标记，此处引用的是 3D Make 入口与模板布局。

以一把需要交付为可编辑 3D 资产的椅子为例，真正需要验收的是：改完椅背高度后，其他部件是否仍然合理；导出之后能否继续编辑；尺寸和结构是否满足实际用途。这些是解释工作流的例子，不是本文对 K3.1 Pro 的实测结果。漂亮的预览只完成了验收的一部分，也不能自动证明某个模型已经满足制造或工程标准。

此前 Qwen3.8-Omni 的成品工作流也体现了类似变化：模型需要围绕一个作品持续工作。这里值得比较的是交付物的结构、可编辑性和返工量，而不是把不同厂商的演示图片摆在一起，就认定已经分出了全面优劣。

高速版快一些，预算也要单独算

Kimi Code 模型配置称，Highspeed 保持相同模型能力，输出速度约为标准版的 2–3 倍，同时消耗约两倍额度。这是厂商的产品说明，不能理解成每一个完整项目都必然快到同样比例：搜索、工具执行和等待人工确认，仍然会占用时间。

国内 API 的官方人民币价格说明也给出了清晰差别。截至核查，标准版每百万词元输入 13 元、输出 68 元；Highspeed 分别为 26 元和 136 元。二者缓存命中均为每百万词元 1.30 元，缓存写入则另按相应规则计算。

用一个简化的假设请求说明：10 万未缓存输入词元，加上接口计费统计中的 1 万输出词元，标准版基础费用为 1.98 元，Highspeed 为 3.96 元。这里没有计算缓存写入、工具、税费和重试，也不是完成某类真实任务的报价。推理过程与反复修改可能改变实际用量，不能只数最后答案的字数。

产品入口也有区别。在 Kimi Code，Plus／Moderato 及以上可以使用标准版，Pro／Allegretto 及以上才解锁最高 100 万上下文与 Highspeed。网页、工作台和开发者 API 的权益应分别核对，会员费用不包含 API 用量。模型支持的上下文上限，不代表每一种订阅入口都开放同样长度。

评测成绩要连同测试条件一起看

月之暗面报告，K3.1 Pro 在 Terminal-Bench 4.0 得到 65.7%，其对照表中的 Opus 5.5 为 66.4%。这是一个具体编程测试中的接近，不能由此推成所有任务表现一致，更不能把“只差零点几个百分点”当作已经证明两者相同。

Terminal-Bench 官方的方法说明表明，4.0 调整了任务资源、修复了任务并移除了部分饱和项目，统一任务超时为 8 小时。任务版本、运行环境和智能体框架都会影响结果；查看不同来源的分数时，应先确认这些条件是否相同。

金融研究方面，发布文强调了文档检索、跨资料核对与多步计算，也报告内部事实准确性压力测试有所改善。压力测试中的错误比例，不是日常所有回答的统一出错率。对一份研究报告而言，来源能否打开、引用是否对应结论、计算是否能复核，仍然是比流畅表达更具体的验收要求。

例如，把几份不同季度的财报整理成同一张比较表，不只是把数字搬进格子。它还涉及币种、单位、合并范围和统计截止时间。最后应该能够追溯每一个关键数字来自哪份资料、哪一段说明，以及表中公式如何使用它们。这是一个说明验收要求的假设场景；模型在内部测试中提高了多少分，不能代替对这份具体交付物的检查。

The Next Web 的报道交叉确认了此次上线和后续权重计划，同时明确指出发布成绩来自月之暗面，未经独立核验。它还关注到厂商在训练中降低网络攻击能力的措施；这同样是有特定测试口径的安全工作，不能写成模型从此没有滥用风险。

K3.1 Pro 之后最值得检查的进展，是这些作品在实际项目里需要多少返工，以及 11 月的权重交付能否按计划完成。对准备尝试的读者，一个规模明确、能核对结果的小项目，比一串覆盖不同任务的排行榜名次更有参考价值。

资料核查截至 2026 年 10 月 25 日。本文未独立运行模型评测；各项能力、费率和开放条件以相应版本的官方说明为准。

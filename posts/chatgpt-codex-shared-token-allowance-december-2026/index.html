ChatGPT 与 Codex 12月将共享额度：Instant聊天不扣，影响有多大？

狂人哥2026-11-02— 次阅读
SI&AI资讯

ChatGPT 的聊天、研究和编程入口正在靠近，订阅额度也将跟着改变。OpenAI 新增的用量说明写明：从12月起，Plus、Pro、Business 的用量将在 ChatGPT 与 Codex 之间共享，并以 token 计量。

对付费用户来说，这比多一个功能按钮更值得留意。未来使用某项高消耗能力，可能影响同一预算还能支持多少其他工作。不过，这份说明同时给了一个明确例外：Instant 聊天不消耗这份用量。

因此，“ChatGPT 与 Codex 共享额度”不等于“以后每句闲聊都挤占编程额度”。截至11月2日，官方也没有公布所有套餐的统一 token 总量和完整切换细则，现在还无法据此判断每个人究竟能多用还是少用。

这次真正新增的，是 ChatGPT 主体验与预算的关系

先把目前的规则理顺。ChatGPT Work 与 Codex 说明把 Work 定位为处理较长、多步骤任务并交付结果的智能体，Codex 则侧重软件开发。两者现在就采用相同的用量结构，并非到了12月才第一次共享预算。

新公告的背景，是把 Work 的智能体能力带进 ChatGPT 主体验，同时调整 ChatGPT 与 Codex 的用量关系。未来用户不一定要先想清楚“这属于聊天还是工作”，再跳到另一个入口；但越接近统一入口，越需要看清一次任务究竟从哪里计量。

官方对 Instant 的原句是：

Instant chat will not draw from your usage.

也就是 Instant 聊天不会扣这份用量。这个例外很关键，却不应被扩写成“所有聊天模型都不计量”或“所有模式都无限使用”。新说明没有给出足够详细的模型与功能对应表，不能凭当前界面里的每个选项，提前填完12月的规则。

Crypto Briefing 的报道把潜在影响概括为：重度编程与聊天开始竞争同一份预算。这抓住了共享的方向，但如果省略 Instant 例外，就会让只看标题的人得到过宽的结论。判断新闻时，应保留官方明确写出的条件。

共享也未必只带来一种结果。如果未来总预算与换算安排合理，偏重一种工作的人可能更容易调配用量；如果同一个账户同时承担大量研究和编程，多个任务也可能更快用完共同预算。这是对机制的分析，不是已经完成的账户测试，更不是官方承诺的每位用户收益。

为什么现在还算不出“合并后缩水多少”

决定实际体验的，并不只有是否共享，还有预算总量、任务消耗和重置规则。官方目前说的是“12月”，没有在这份新说明中给出精确切换日，也没有列出每档包含多少 token、现有额度如何转换，以及每个具体功能的映射。

这份新说明点名的是 Plus、Pro、Business。其他套餐和企业合同是否采用相同安排，仍需要相应的官方说明，不能直接把这三个名称扩展成所有账户。

token 本身也不是消息条数。现行计价文档解释，提示词、文件、聊天历史、工具返回结果和模型回答都会涉及 token；输入、缓存输入与输出又有不同的计量口径。把一条短问题与一个反复读文件、调用工具的长任务，都算作“问了一次”，无法反映二者的资源消耗。

Codex 订阅说明还列出了模型、上下文、推理、速度、工具和任务复杂度等影响因素。这意味着，即便两个人购买同一套餐，完成的工作数量也可能很不同。一次任务是否反复扩展范围、是否不断读入无关内容，会影响预算能支撑多久。

但这也不意味着可以拿 API 单价反推订阅总量。官方计价页明确提醒：API 价格与套餐内含用量分开，积分费率本身不能决定订阅包含多少任务。网上若出现“200美元一定等于某个固定 token 数”的计算，应先看它有没有得到对应套餐的官方依据。

OpenAI 表示，它预计多数用户不会比现在更频繁地等待额度重置，并将提供合并后的剩余用量和重置时间。这是公司对过渡的预期；真正是否做到，要等规则实施和实际使用结果，不能把预期直接写成已经验证的改善。

当前额度调整与12月合并，需要分开判断

近期Pro 200 原定削减被撤回，已经引发对订阅可预期性的讨论。Pro 套餐帮助页目前确认，原削减取消，较低的旧用量档向上对齐，200美元月价保持不变。这些是当前已经公布的调整，不能因为出现12月的新机制，就重新认定那次削减又生效了。

还要区分套餐内含用量与额外购买的积分。个人计划弹性积分说明目前采用先使用内含额度、超限后使用可用积分的规则；购买资格和支持功能因账户而异。这些订阅用量积分也不是开发者 API 积分。现行规则能帮助理解账本，却不能替代尚未公布的12月转换方案。

这次新闻透露的产品方向很清楚：OpenAI 希望用户围绕同一个 ChatGPT 账户，在对话、研究、交付和编程之间连续工作。对订阅者更重要的考验则是，入口简化之后，账本能否同样清楚。

接下来值得跟进的是正式实施通知：哪些活动计入共同预算、每档究竟获得多少、何时重置，以及跨入口任务的消耗能否看明白。在这些细则出现前，保留 Instant 例外与未来实施这两个前提，比提前宣布全面涨价、减半或无限用，都更接近已经证实的消息。
